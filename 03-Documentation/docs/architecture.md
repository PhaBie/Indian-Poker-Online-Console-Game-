# Architecture & Design

โปรเจกต์นี้ได้รับการออกแบบเพื่อรองรับการทำงานแบบ Multiplayer Real-time บน Console โดยใช้เทคโนโลยีรันไทม์ Bun ร่วมกับ TypeScript

## โครงสร้างการทำงานของระบบ (Client-Server)

ระบบแบ่งหน้าที่หลักออกเป็น 3 ส่วนอย่างชัดเจน:

### 1. Client (ส่วนแสดงผลและรับคำสั่ง)

- ทำหน้าที่แสดงหน้าจอเกมผ่าน Terminal (ใช้ React + Ink)
- รับคำสั่งและ Input จากผู้เล่น
- ส่ง Action ไปยัง Server ผ่าน WebSocket
- **จะไม่ตัดสินใจ Logic ใดๆ เลย** เป็นเพียงแค่ View

### 2. Server (ส่วนควบคุมเกมหลัก)

- เป็นตัวควบคุมเกมทั้งหมดและเป็น Single Source of Truth
- ตรวจสอบว่า Action ของ Client นั้นถูกต้องและสามารถทำได้หรือไม่
- จัดการการเชื่อมต่อ WebSocket และ Session ของผู้เล่น
- ป้องกันการโกงโดยจะไม่ส่งข้อมูลไพ่ที่คว่ำอยู่ให้ผู้เล่นคนอื่น

### 3. Game Logic / Game State (ส่วนกติกาและสถานะ)

- เก็บกติกาและสถานะของเกม เช่น:
  - จำนวน Chips ของผู้เล่น
  - ไพ่ที่แจกให้แต่ละคน
  - จำนวนเงินรวมใน Pot
  - ลำดับเทิร์นและผู้เล่นที่กำลังตัดสินใจ

## หลักการออกแบบสถาปัตยกรรม

1. **การแยกส่วน (Separation of Concerns):** แยกฝั่งหน้าจอแสดงผลออกจากระบบประมวลผลเกม ช่วยให้รื้อทำ UI ใหม่ได้โดยไม่กระทบ Logic
2. **การสนับสนุน TDD (Testability):** ส่วนกติกา (`src/server/core`) แยกตัวเป็นอิสระ ทำให้ง่ายต่อการเขียน Unit Test ควบคุมกรณี Edge cases ได้ง่าย
3. **มาตรฐานการสื่อสาร:** ใช้ `src/shared/` เป็นตัวกลางกำหนด Data Types และ Format ของข้อความ ทำให้ Client และ Server สื่อสารบนมาตรฐานเดียวกันเป๊ะ
4. **การรองรับการขยายตัว (Maintainability):** โครงสร้างแบบ Clean/Domain-Driven Architecture ช่วยให้ระบบจัดการง่ายเมื่อมีฟีเจอร์ใหม่

## ข้อจำกัดที่ทราบ (Known Limitations)

ระบบยังมีข้อจำกัดบางส่วนในเวอร์ชันปัจจุบัน:

1. ขนาดหน้าจอ Terminal จำเป็นต้องใช้อย่างน้อย 150x41 เพื่อแสดงผลได้ครบถ้วน
2. ไม่รองรับการทำงานบางอย่างตามที่มีระบุไว้ในข้อจำกัดเดิม (เช่น อาจยังไม่ครอบคลุมผู้เล่นเกิน 4 คน หรือข้อจำกัดเครือข่ายบางประการ)
