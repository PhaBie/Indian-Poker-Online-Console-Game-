# โครงสร้างและวงจรการทำงานของระบบ (Project Structure & Lifecycle)

ภาพรวมระบบ Indian Poker Online (Teen Patti)

สถาปัตยกรรม: Client-Server, สื่อสารแบบ Real-time ผ่าน WebSocket
เทคโนโลยี: TypeScript + Bun, React + Ink (วาดหน้าจอบน Terminal), ws, Zod

เอกสารนี้อธิบายว่าระบบทำงานอย่างไรตั้งแต่ต้นจนจบ และแต่ละไฟล์หลักมีหน้าที่อะไร

Client แสดงหน้าจอและส่งคำสั่งของผู้เล่นเท่านั้น
Server เป็นผู้ตัดสินทุกอย่าง: ใครชนะ ใครมีชิปเท่าไหร่ ใครทำอะไรได้
Game Logic แยกเป็นอิสระจากส่วนอื่น จึงเขียน Unit Test ได้ง่าย

ส่วนที่ 1: ระบบทำงานอย่างไร
ขั้นที่ 1: เปิดเซิร์ฟเวอร์
รันจุดเริ่มต้น server/index.ts (Local) หรือ server/online.ts (Online ผ่าน Ngrok)
Server เปิด WebSocket รอผู้เล่น และเตรียม RoomManager ไว้จัดการห้อง

ขั้นที่ 2: ผู้เล่นเชื่อมต่อ
ผู้เล่นเปิดเกม กรอก IP เซิร์ฟเวอร์และชื่อ
Client ส่งคำขอเชื่อมต่อไปที่ Server
socketHandler.ts รับการเชื่อมต่อ และให้ validator.ts เช็คข้อมูล เช่น ชื่อถูกรูปแบบไหม ยาวเกินไปไหม
ถ้าผ่าน การเชื่อมต่อสำเร็จ และผู้เล่นได้ reconnectToken ไว้ใช้กลับเข้าห้องเดิมถ้าเน็ตหลุด

ขั้นที่ 3: สร้างห้องและเข้าห้อง
ผู้เล่นเลือก สร้างห้อง (ตั้งค่า Boot Amount ได้) หรือ เข้าห้องด้วย Room ID / Room Browser
RoomManager สร้าง Room และนำ Player ใส่เข้าไปในห้อง
ห้องรองรับ 2-4 คน ต้องมีอย่างน้อย 2 คนจึงเริ่มเกมได้
คนที่เข้าห้องระหว่างเกมกำลังเล่นอยู่ ต้องรอจนจบรอบก่อน
Host กดเริ่มเกม ห้องเปลี่ยนสถานะและเรียก Game Logic

ขั้นที่ 4: ลูปของเกม (1 รอบ)
เริ่มรอบ → หัก Boot เข้า Pot → แจกไพ่คว่ำ 3 ใบ → วนเทิร์นเดิมพัน → จบรอบ → จ่าย Pot → เริ่มรอบใหม่

ตอนเริ่มรอบ

gameLogic.ts สับไพ่ (กำหนด Seed ได้ เพื่อใช้ทดสอบ) และแจกคนละ 3 ใบ แบบคว่ำหน้า
ทุกคนเริ่มเป็น Blind (ยังไม่ได้ดูไพ่ตัวเอง)

ในแต่ละเทิร์น: ผู้เล่นเลือกทำอย่างใดอย่างหนึ่ง

คำสั่ง ความหมาย
SEEN เปิดดูไพ่ตัวเอง กลายเป็น Seen และจ่ายเดิมพันแพงขึ้น 2 เท่า
CALL จ่ายตามเดิมพันปัจจุบัน
BET / RAISE เพิ่มเดิมพัน ทุกคนต้องจ่ายตาม
FOLD หมอบ ออกจากรอบนี้
SHOW เปิดไพ่เทียบกัน (ใช้ได้เมื่อเหลือ 2 คน)

เส้นทางของคำสั่งแต่ละครั้ง

Client ส่งคำสั่ง
→ validator.ts เช็คว่าข้อมูลถูกรูปแบบไหม (เช่น จำนวนเงินเป็นตัวเลขถูกต้อง)
→ accessPolicy.ts เช็คสิทธิ์ (ใช่ตาคนนี้ไหม? ทำคำสั่งนี้ได้ไหม?)
→ gameLogic.ts ประมวลผลตามกติกา
→ GameState.ts อัปเดตสถานะ (ไพ่ เงิน ตา)
→ Server ส่งข้อมูลที่กรองแล้ว (DTO) ให้ทุกคน

การซ่อนไพ่ (ระบบป้องกันการโกง): Server ตัดไพ่ของผู้เล่นคนอื่นออกก่อนส่งทางเครือข่ายเสมอ Client จึงไม่มีทางรู้ไพ่ของคู่แข่ง จนกว่าจะจบรอบและเปิดไพ่จริง

จบรอบ ได้ 2 แบบ

ทุกคนหมอบจนเหลือคนเดียว → คนนั้นชนะทันที ไม่ต้องเปิดไพ่
มีการ SHOW → gameLogic.ts เทียบไพ่ ผู้ชนะรับ Pot แล้วเริ่มรอบใหม่

ส่วนที่ 2: หน้าที่ของแต่ละไฟล์
🧠 Core Logic (สมองของเซิร์ฟเวอร์)

server/core/gameLogic.ts

- ศูนย์รวมกติกาเกม สับไพ่ (shuffleDeck) แจกไพ่ (dealCards) หาผู้ชนะ (calculateWinner) รับ GameState เข้าไปแล้วคืน GameState ใหม่ที่อัปเดตแล้ว

server/domain/services/RoomManager.ts

- ผู้จัดการห้องทั้งหมด เก็บรายการห้องที่เปิดอยู่ มี createRoom(), joinRoom(), leaveRoom() ห้องที่คนออกหมดจะถูกลบทิ้ง

📦 Models (โครงสร้างข้อมูล)
server/domain/models/Room.ts

- ห้อง 1 ห้อง ชื่อห้อง, รหัสห้อง, รายชื่อ Player, และ GameState ของห้อง

server/domain/models/Player.ts

- ผู้เล่น 1 คน ชื่อ, Socket ID, ไพ่ในมือ 3 ใบ, ชิปที่เหลือ, สถานะ Blind/Seen

server/domain/models/GameState.ts

- สถานะเกม "ณ ตอนนี้" เฟสของเกม (รอเริ่ม / กำลังเล่น / จบรอบ), ตาของใคร, เงินใน Pot

shared/types.ts

- ไฟล์กลาง โครงสร้างข้อมูล (DTO) ที่ Client กับ Server ใช้ร่วมกัน และกำหนดว่าส่งได้เฉพาะข้อมูลสาธารณะ ห้ามส่งไพ่ที่ต้องซ่อน

🌐 Network (รับส่งข้อมูลและความปลอดภัย)
server/network/socketHandler.ts

- รับ Event ต่างๆ (เช่น BET) ดึงข้อมูลห้อง แล้วเรียก gameLogic ให้ทำงาน

server/network/validator.ts

- เช็คชนิดและรูปแบบข้อมูลจาก Client (ใช้ Zod) เช่น ความยาวชื่อ, จำนวนเงินต้องเป็นตัวเลขที่ถูกต้อง

server/network/accessPolicy.ts

- เช็คสิทธิ์ก่อนทำงานต่อ เช่น canPlayerBet(), canPlayerStartGame() กันการส่งคำสั่งผิดตาหรือโกง

ความต่างที่ต้องจำ: validator ถามว่า "ข้อมูลถูกรูปแบบไหม" ส่วน accessPolicy ถามว่า "คนนี้มีสิทธิ์ทำสิ่งนี้ไหม"

🖥️ Client (ฝั่งหน้าจอผู้เล่น)
client/network/SocketClient

- จัดการ WebSocket ฝั่งผู้เล่น

client/state/ClientState

- เก็บสถานะที่ได้รับจาก Server

client/ui/screens/

- หน้าจอต่างๆ เช่น Lobby, Waiting Room, Game, Result

ไฟล์ use...Controller.ts, useDealSequenceTracker.ts

- คอยดูสถานะที่เปลี่ยนจาก Server แล้วคุมจังหวะแอนิเมชัน (เช่น รอบใหม่ให้สับไพ่ใหม่) และส่ง Input ของผู้เล่นไปหา Server
