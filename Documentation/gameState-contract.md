# แผนการพัฒนา Test Suite สำหรับ GameState (15 Methods)

แผนนี้มุ่งเน้นการจัดระเบียบและเพิ่มเติมชุดทดสอบ (`gameState.test.ts`) ให้ครอบคลุมการทำงานของ `GameState` ตามข้อกำหนดที่ชัดเจนแล้ว **โดยจะยังคงรักษาเคสทดสอบเดิมทั้ง 20 เคสไว้** และจะนำมาจัดกลุ่ม (Happy/Unhappy Paths) รวมถึงเพิ่มเติมเคสที่ยังขาดหายไป ไม่มีการรื้อของเดิมทิ้งและไม่แก้ Implementation จริง

---

## รายการข้อกำหนดของทั้ง 15 เมธอดที่ชัดเจนแล้ว (พร้อมเขียนเทสต์)

### 1. `startGame()`

- **เงื่อนไขก่อนเรียก**: มีผู้เล่น 2 คนขึ้นไป
- **ผลลัพธ์**:
  - หักชิปตามตัวแปร `bootAmount` ของรอบนั้นๆ (สามารถระบุเองตอนสร้าง GameState ได้)
  - นำเงิน Boot ทุกคนไปรวมไว้ใน `pot`
  - แจกไพ่คนละ 3 ใบ ไม่ซ้ำกัน (ไพ่ในมือ + ไพ่เหลือในกอง = 52 ใบ)
  - ผู้เข้าร่วมทุกคนสถานะเป็น `ACTIVE` และ `isBlind = true`
- **ข้อจำกัด (Boot ไม่พอ)**: หากตอนเริ่มเกม มีคนใดคนหนึ่งมีเงินไม่พอค่า Boot ระบบจะปฏิเสธการเริ่มรอบทันที โดยโยน `InsufficientChipsError` และต้องไม่มีการดึงเงินหรือแจกไพ่ให้ใครเลย (สเตตัสทุกคนคงเดิม)
- **การรักษาข้อมูล (Atomicity)**: หากมีการโยน Error ใดๆ เกิดขึ้น เงิน ไพ่ และสถานะต้องไม่เปลี่ยน

### 2. `nextTurn()` / `rotateDealer()`

- **การแยกความรับผิดชอบ**: การกระทำ (Action) เช่น BET, CALL, RAISE จะ **ไม่เลื่อนตาเอง** ผู้ควบคุม (Server/Room) ต้องเป็นผู้ตรวจจบรอบก่อน แล้วจึงเรียก `nextTurn()` หากยังมีคนเล่นต่อ
- **ผลลัพธ์ `nextTurn()`**:
  - เลื่อน `currentPlayerIndex` ไปไปยัง `ACTIVE` ถัดไป และวนกลับไปที่ต้นแถวได้ ข้ามคนที่ `FOLDED`, `DISCONNECTED`, `WAITING` ได้หลายคนติดกัน
  - หากไม่มีผู้เล่นที่มีสถานะ `ACTIVE` เหลืออยู่เลย ระบบจะทำการโยน `PlayerStateError`
  - **หากเหลือ ACTIVE เพียงคนเดียว**: ระบบต้องไม่เลื่อนตาต่อ (ค้างไว้) และไม่เปลี่ยนเงินหรือไพ่ใดๆ (รอจบรอบ)
- **ผลลัพธ์ `rotateDealer()`**: เลื่อนตำแหน่ง Dealer ไปยังผู้เล่นคนถัดไป และสามารถวนกลับมาที่ผู้เล่นคนแรกได้
- **สิ่งที่คงเดิม**: การเปลี่ยนตาหรือสลับดีลเลอร์ต้องไม่เปลี่ยนยอดเงินหรือไพ่ของใคร

### 3. การจัดการ Timeout และ Disconnect

- **`autoFoldTimeout()`**: บังคับหมอบ (Fold) ทันที ผู้เรียก (Caller) ต้องเป็นคนเช็คเองว่า Timer ที่ดังขึ้นยังเป็นของตาปัจจุบันหรือไม่ (เนื่องจากเมธอดไม่มีข้อมูลบอกตาเก่า) และ **ไม่เลื่อนตาเองเด็ดขาด** (ต้องให้ผู้ควบคุมฝั่ง Server จัดการเลื่อนตาเมื่อรอบยังไม่จบ) หลังเปลี่ยนสถานะ ถ้าเหลือ ACTIVE คนเดียว ให้ **จ่าย Pot ให้ผู้รอดทันที** และตั้ง Pot เป็นศูนย์
- **`handlePlayerDisconnect(playerId)`**:
  - เปลี่ยนสถานะเป็น `DISCONNECTED` โดยไม่คืนเงินเดิมพัน และไม่กระทบยอดคนอื่น
  - หากหลุด **นอกตาตัวเอง** -> GameState ไม่เลื่อนตา
  - หากหลุด **ตรงกับตาตัวเอง** -> GameState เลื่อนตาอัตโนมัติ (หรือจบรอบถ้าเหลือ 1 คน)
  - ตัดการเชื่อมต่อซ้ำ (`DISCONNECTED` อยู่แล้ว) ต้องไม่ทำงานซ้ำหรือจ่ายเงินซ้ำ
  - หากเรียกด้วย ID ที่ไม่มีอยู่ ให้โยน `GameError('...', 'PLAYER_NOT_FOUND')`

### 4. `processAction(playerId, action, amount)`

- **เงื่อนไขก่อนเรียก**: เป็นเทิร์นของ `playerId` และผู้เล่นมีสถานะ `ACTIVE` (หากเป็น `WAITING` หรือ `DISCONNECTED` ต้องปฏิเสธ Action)
- **การกำหนดขอบเขต BET/CALL/RAISE ชัดเจน** (ให้ S = currentStake):
  - **BET**: จ่ายเงินระบุจำนวน (Blind: จ่ายระหว่าง S ถึง 2S, Seen: จ่ายระหว่าง 2S ถึง 4S)
  - **CALL**: ยอดขั้นต่ำ (Blind: จ่าย S, Seen: จ่าย 2S)
  - **RAISE**: ยอดเพิ่ม Stake (Blind: จ่ายมากกว่า S ถึง 2S, Seen: จ่ายมากกว่า 2S ถึง 4S)
  - **Stake ใหม่**: เท่ากับ ยอดที่ Blind จ่าย หรือ ครึ่งหนึ่งของยอดที่ Seen จ่าย
  - **ข้อจำกัดทศนิยม**: หากยอดที่ Seen จ่าย เมื่อหารสองแล้วเป็นทศนิยม ต้อง **ปฏิเสธ** (โยน Error) เพราะระบบต้องการ Stake เป็นจำนวนเต็มเสมอ
- **ขอบเขตตัวเลขและ Overflow**: ตรวจจับยอดติดลบ, 0, ทศนิยม, NaN, ±Infinity, ไม่ส่ง amount, ข้อมูลเป็น String, กรณีเงินล้นขีดจำกัดปลอดภัย (`Number.MAX_SAFE_INTEGER`) หรือหากเงินที่รับเข้าบวกกับ Pot แล้วทะลุขีดจำกัด ต้องโยน `INVALID_AMOUNT` ก่อนเปลี่ยนแปลง State ใดๆ
- **SEEN**: การขอดูไพ่ (SEEN) ไม่ใช่การจบตา และการเรียกซ้ำต้องไม่เสียเงินเพิ่ม การเดิมพันครั้งถัดไปของผู้เล่นนี้จะถูกคิดเรท Seen (2x Stake)

### 5. การขอ SHOW (`processAction` ด้วย `SHOW`)

- **เงื่อนไขก่อนเรียก**: ต้องเหลือผู้เล่นที่เล่นต่อได้แค่ 2 คนเท่านั้น (ไม่นับ FOLD/DISCONNECTED) หากมีรวมกันมากกว่า 2 คนใน Array แต่ ACTIVE 2 คน ก็สามารถขอได้
- **ผลลัพธ์**:
  - **Blind ขอ SHOW**: หักชิป 1 เท่าของ Stake (ขอ SHOW กับ Seen ได้)
  - **Seen ขอ SHOW กับ Seen**: หักชิป 2 เท่าของ Stake
  - **Seen ขอ SHOW กับ Blind**: ปฏิเสธ (โยน InvalidActionError)
  - **กรณีไพ่เสมอ (Tie) หรือ ไพ่ต่ำกว่า**: ผู้ขอ SHOW จะเป็นฝ่ายแพ้ทันที! **(นโยบายระบบ: ผู้แพ้จากการขอ SHOW จะถูกเปลี่ยนสถานะเป็น FOLDED เฉพาะรอบปัจจุบัน (รอรีเซ็ตเมื่อเริ่มรอบใหม่) เสมอ เพื่อบังคับให้ออกจากรอบการเล่นนี้)**
- **สิ่งที่คงเดิม**: หากเงินไม่พอจ่ายค่า SHOW จะไม่มีการหักเงิน และ State คงเดิม

### 6. ผู้ชนะและการจบรอบ (`evaluateWinner`, `checkLastManStanding`, `endGame`)

- **ผลลัพธ์**:
  - `checkLastManStanding()`: ประเมินเฉพาะผู้เล่นที่มีสถานะ `ACTIVE` หากเหลือเพียง 1 คนให้ส่งคืนคนนั้น หากเหลือ 0 คนหรือมากกว่า 1 คน (หรือ Array ว่าง) ให้คืนค่า `null` โดยไม่เปลี่ยนแปลง State ใดๆ
  - `endGame()`: โอนเงิน `pot` ให้ผู้ชนะเพียงผู้เดียว
  - `evaluateWinner()`: โอนเงินใน Pot ให้คนหน้าไพ่ชนะ
  - **กรณีผู้เล่นที่หมอบ, รอ, หรือตัดการเชื่อมต่อ**: (`FOLDED`, `WAITING`, `DISCONNECTED`) แม้ถือไพ่ดีสุดก็จะไม่ได้รับรางวัลใดๆ
  - **การจ่ายซ้ำ**: การเรียกจบรอบซ้ำอีกครั้ง ต้องไม่จ่ายเงินซ้ำเป็นครั้งที่ 2

### 7. การเสมอและการแบ่งเศษชิป (`handleTie`)

- **การแบ่งชิป**: อิงผลลัพธ์เศษตามกลไก `calculateSplitPot` ของ Core แต่ในชุดทดสอบ GameState จะ Hardcode ตัวเลขและผู้ชนะตามลำดับ เพื่อป้องกันการสร้าง Expected ด้วยฟังก์ชันเดียวกันกับ Implementation ซึ่งอาจผิดพลาดเหมือนกัน
- **การรักษาสมดุลชิป**: ผลรวมของชิปทุกคนในห้อง + เงินใน Pot ก่อนจ่ายรางวัล ต้อง **เท่ากับ** หลังจ่ายรางวัลแล้ว

### 8. Pot Limit (`checkPotLimitReached`)

- **ผลลัพธ์**: ตรวจว่า Pot < Limit, == Limit, > Limit ได้ (ใช้ค่า Limit อื่่นๆ ที่ไม่ใช่ 10000 ได้)
- การเรียกตรวจนี้ต้องไม่เปลี่ยนแปลง State ข้อมูลใดๆ

### 9. กติกาการดวลไพ่ Sideshow / DUEL (`processAction`)

- **การเรียกใช้และคำศัพท์**: ภายในระบบ (Domain/Network/State) ใช้ชื่อ `SIDESHOW` ส่วนหน้าจอ UI ผู้เล่นแสดงผลเป็น `DUEL`
- **เงื่อนไขการขอ**:
  - ต้องเหลือผู้เล่นสถานะ `ACTIVE` มากกว่า 2 คนขึ้นไป
  - ผู้เล่น `ACTIVE` ทุกคนต้องดูไพ่แล้ว (`isBlind === false`)
  - ต้องเป็นตาเล่นของผู้ขอ (`challenger`) และมีชิปเพียงพอสำหรับจ่าย `currentStake * 2`
  - เป้าหมาย (`target`) คือผู้เล่นก่อนหน้าที่ยังคงสถานะ `ACTIVE`
- **การตอบรับคำขอ**:
  - ผู้เล่นเป้าหมายเลือก `ACCEPT_SIDESHOW` หรือ `REJECT_SIDESHOW`
  - `ACCEPT_SIDESHOW`: เปรียบเทียบไพ่ระหว่างผู้ขอและเป้าหมาย ผู้มีไพ่ต่ำกว่าจะเปลี่ยนสถานะเป็นหมอบ (`FOLDED`) หากไพ่เสมอกันทุกใบ ผู้ขอเป็นฝ่ายหมอบตามกติกา Teen Patti
  - `REJECT_SIDESHOW`: ไม่มีผู้เล่นคนใดหมอบ ไม่มีการเปิดเผยไพ่ และบันทึก `lastSideshowNotice` สถานะ `DECLINED`
- **การรักษาความลับของไพ่ (Card Privacy)**: ข้อมูลไพ่ในการดวลจะถูกส่งผ่าน Network Payload ให้เฉพาะผู้ขอและเป้าหมายเท่านั้น ผู้เล่นคนที่สามและผู้ชมจะได้รับ `sideshowResult: null` และไม่มีข้อมูลไพ่รั่วไหล
- **ผลลัพธ์หลัง Sideshow**: เกมดำเนินต่อไปยังผู้เล่นคนถัดไป เว้นแต่ผลการดวลทำให้เหลือผู้เล่นคนเดียวในโต๊ะ จะจบรอบและจ่าย Pot ทันที
