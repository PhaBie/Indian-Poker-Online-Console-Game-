## รายการข้อกำหนดของทั้ง 15 เมธอดที่ชัดเจนแล้ว (พร้อมเขียนเทสต์)

### 1. `startGame()`

- **เงื่อนไขก่อนเรียก**: มีผู้เล่น 2 คนขึ้นไป
- **ผลลัพธ์**:
  - หักชิปตามตัวแปร `bootAmount` ของรอบนั้นๆ (สามารถระบุเองตอนสร้าง GameState ได้)
  - นำเงิน Boot ทุกคนไปรวมไว้ใน `pot`
  - แจกไพ่คนละ 3 ใบ ไม่ซ้ำกัน (ไพ่ในมือ + ไพ่เหลือในกอง = 52 ใบ)
  - ผู้เข้าร่วมทุกคนสถานะเป็น `ACTIVE` และ `isBlind = true`
- **สิ่งที่คงเดิม**: ลำดับผู้เล่น, ผู้เล่นสถานะที่ไม่เกี่ยว
- **การรักษาข้อมูล (Atomicity)**: หากมีการโยน Error ใดๆ เกิดขึ้น เงิน ไพ่ และสถานะต้องไม่เปลี่ยน

### 2. `nextTurn()` / `rotateDealer()`

- **เงื่อนไขก่อนเรียก**: เกมกำลังอยู่ในช่วงเล่น
- **ผลลัพธ์**:
  - `nextTurn()` เลื่อน `currentPlayerIndex` ไปยัง `ACTIVE` ถัดไป และวนกลับไปที่ต้นแถวได้ ข้ามคนที่ `FOLDED`, `DISCONNECTED` ได้หลายคนติดกัน
  - หากไม่มีผู้เล่นที่มีสถานะ `ACTIVE` เหลืออยู่เลย ระบบจะทำการโยน `PlayerStateError` (ไม่ใช่การป้องกันลูปด้วยเงื่อนไขทางโค้ดปกติ แต่บังคับจบด้วย Error)
  - `rotateDealer()`: เลื่อนตำแหน่ง Dealer ไปยังผู้เล่นคนถัดไป และสามารถวนกลับมาที่ผู้เล่นคนแรกเมื่อถึงท้ายแถวได้ (การหมุน Index ปกติ)
- **สิ่งที่คงเดิม**: การเปลี่ยนตาหรือสลับดีลเลอร์ไม่เปลี่ยนยอดเงินหรือไพ่ของใคร

### 3. `processAction(playerId, action, amount)`

- **เงื่อนไขก่อนเรียก**: เป็นเทิร์นของ `playerId` และผู้เล่นมีสถานะ `ACTIVE`
- **ผลลัพธ์ / การตรวจสอบ Boundary**:
  - รองรับ ACTION: BET, CALL, RAISE, FOLD, SEEN, SHOW อย่างชัดเจน
  - ขอบเขตตัวเลข (เฉพาะเคสทดสอบปัจจุบันรองรับ `RAISE`): ตรวจจับยอดติดลบ, 0, ทศนิยม, NaN, ±Infinity, ข้อมูลเป็น String และกรณีเกิน `Number.MAX_SAFE_INTEGER`
  - การเล่นต่อเนื่องหลาย Action ต้องคำนวณยอดเงินสะสมได้ถูกต้อง
  - FOLD: เปลียนสถานะโดยไม่คืนเงิน
  - SEEN: เปลี่ยนเป็น Seen ไม่หักเงิน
- **สิ่งที่คงเดิม (Atomicity)**: หากระบุค่าที่ผิด (เช่นยอดเงินติดลบ, ทศนิยม) ระบบจะโยน `GameError` รหัส `INVALID_AMOUNT`, หาก Action ไม่รู้จัก, หรือเล่นนอกตา ต้องโยน Error ตาม Contract, หรือ **หาก ID ของผู้เล่นไม่มีอยู่ในห้อง ระบบจะโยน `GameError` รหัส `PLAYER_NOT_FOUND`** ชิป สถานะ ไพ่ ต้องไม่เปลี่ยนแปลงบางส่วน

### 4. การขอ SHOW (`processAction` ด้วย `SHOW`)

- **เงื่อนไขก่อนเรียก**: ต้องเหลือผู้เล่นที่เล่นต่อได้แค่ 2 คนเท่านั้น (ไม่นับ FOLD/DISCONNECTED)
- **ผลลัพธ์**:
  - **Blind ขอ SHOW**: หักชิป 1 เท่าของ Stake
  - **Seen ขอ SHOW กับ Seen**: หักชิป 2 เท่าของ Stake
  - **Seen ขอ SHOW กับ Blind**: ปฏิเสธ (โยน InvalidActionError)
  - **กรณีไพ่เสมอ (Tie)**: **ผู้ขอ SHOW จะเป็นฝ่ายแพ้ทันที!** ต้องแยกประเด็นนี้ออกจากการเสมอแบบปกติ (handleTie)
- **สิ่งที่คงเดิม**: สถานะของไพ่ผู้เล่นอื่น
- **Error ที่คาดหวัง**: ขอ SHOW นอกตา, ขอตอนมีคนเล่นเกิน 2 คน, เงินไม่พอ

### 5. ผู้ชนะและการจบรอบ (`evaluateWinner`, `checkLastManStanding`, `endGame`)

- **ผลลัพธ์**:
  - `checkLastManStanding()`: ประเมินเฉพาะผู้เล่นที่มีสถานะ `ACTIVE` หากเหลือเพียง 1 คนให้ส่งคืนคนนั้น หากเหลือ 0 คนหรือมากกว่า 1 คนให้คืนค่า `null`
  - `endGame()`: โอนเงิน `pot` ให้ผู้ชนะเพียงผู้เดียว ไม่ประเมินไพ่
  - `evaluateWinner()`: โอนเงินใน Pot ให้คนหน้าไพ่ชนะ
  - **กรณีผู้เล่นที่หมอบหรือตัดการเชื่อมต่อ**: แม้ถือไพ่ดีสุดก็จะไม่ได้รับรางวัลใดๆ
  - **การจ่ายซ้ำ**: การเรียกจบรอบซ้ำอีกครั้ง ต้องไม่จ่ายเงินซ้ำเป็นครั้งที่ 2

### 6. การเสมอทั่วไป (`handleTie`)

- **ผลลัพธ์**:
  - แบ่ง `pot` ตามจำนวน `winners` และจัดการเศษตามข้อตกลง
  - **การรักษาสมดุลชิป**: ผลรวมของชิปทุกคนในห้อง + เงินใน Pot ก่อนจะมีการจ่ายรางวัล ต้อง **เท่ากับ** ผลรวมของชิปทุกคนในห้อง + เงินใน Pot หลังจ่ายรางวัลแล้ว (เงินห้ามหายและห้ามเสกเพิ่ม)

### 7. Pot Limit (`checkPotLimitReached`)

- **ผลลัพธ์**:
  - ตรวจว่า Pot < Limit, == Limit, > Limit และใช้ Limit แบบ Custom ได้
  - การเรียกตรวจนี้ต้องไม่เปลี่ยนแปลง State ข้อมูลใดๆ

### 8. งานที่พักไว้ (Skipped Scope)

- `executeSideshow` และ `rejectSideshow` มีความซับซ้อนและยังขาดข้อสรุป จึงระบุชัดเจนว่าเป็น **"พักหลังเดโม"** จะถูกคงสถานะ Skip ไว้และไม่คาดเดากติกาเอง
