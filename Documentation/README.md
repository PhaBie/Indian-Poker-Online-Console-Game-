# เอกสารโครงการสำหรับทีมพัฒนา

เอกสารชุดนี้อธิบายสิ่งที่เตรียมไว้ใน PR #9 และแนวทางรับงานไปพัฒนาต่อ

| เอกสาร | เนื้อหา |
| --- | --- |
| [บันทึกการปรับปรุงใน PR นี้](บันทึกการปรับปรุง-PR9.md) | สิ่งที่เปลี่ยน เหตุผล และสถานะของระบบหลังเตรียมโครงสร้าง |
| [คู่มือพัฒนาและแบ่งงาน](คู่มือพัฒนาและแบ่งงาน.md) | หน้าที่ของแต่ละไฟล์ งานที่ต้องทำ Test ที่เกี่ยวข้อง และการเชื่อมงานระหว่างทีม |

## แนวทางเริ่มงาน

1. อ่านบันทึกการปรับปรุงเพื่อเข้าใจพื้นฐานที่มีอยู่
2. ใช้คู่มือพัฒนาตกลงผู้รับผิดชอบแต่ละส่วน โดยคนหนึ่งรับได้หลายส่วน
3. เปิด Source คู่กับ Test ของงานที่รับผิดชอบ แล้วพัฒนาทีละพฤติกรรม
4. ตกลงรูปแบบข้อมูลร่วมกับผู้รับงานต่อก่อนเปลี่ยน shared types หรือ signature
5. ส่ง PR พร้อมผลตรวจและระบุส่วนที่ยังรอการเชื่อมต่อ

ไฟล์ `core_functions_for_tdd.txt` เป็นรายการออกแบบเดิม ชื่อและ signature บางส่วนต่างจากโค้ดปัจจุบัน เช่น `determineWinners` ซึ่งปัจจุบันใช้ `getWinners` ให้ใช้ Source และ Test ปัจจุบันประกอบคู่มือ หากพบข้อขัดแย้งให้ตกลงกติกาก่อนแก้ไข

สถานะปัจจุบันพร้อมให้ทีมเริ่มพัฒนา แต่ฟังก์ชันส่วนใหญ่ยังเป็น Stub และยังไม่ใช่เกมที่เล่นได้ครบวงจร
